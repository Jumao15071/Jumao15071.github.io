BedrockMap

来源：README.zh-CN.md

English | 简体中文

BedrockMap 是一款基于 Qt6 和 C++17 构建的、完全开源的《我的世界》基岩版地图编辑器。它提供了一套全面的工具，用于浏览、检查和编辑基岩版世界存档（LevelDB 格式），支持所有维度。

功能特性

  • 世界浏览 — 打开并探索主世界、下界和末地，以及自定义维度的基岩版世界
  • 地形可视化 — 生物群系地图和地形叠加层，支持可配置的渲染过滤
  • 区块编辑器 — 选择、检查和删除区块；可视化区块实体、方块实体和计划刻（pending ticks）
  • 区块复制粘贴 — 复制选中区域并粘贴到其他世界，甚至跨存档，支持交互式放置
  • NBT 编辑器 — 查看和修改 NBT 数据，包括 level.dat、玩家物品栏、村庄、地图物品等
  • mcstructure 支持 — 浏览和编辑 .mcstructure 文件（带 3D 体素预览），并可将选中区域或区块导出为 .mcstructure 文件
  • 体素渲染 — 选中区域的 3D 体素可视化，可导出为 GLB 模型
  • 多标签工作区 — 同时打开和管理多个世界

下载

从 Release 页面 下载最新版本。

系统要求

  • 操作系统 — Windows 10

快速上手

通过 文件 → 打开世界（Ctrl+O）打开世界，或直接将世界文件夹、.mcstructure、.nbt 文件拖入窗口。

地图视图中：左键拖动平移，右键打开菜单，滚轮按下拖动框选区域，滚动滚轮缩放。

常用快捷键：

快捷键 功能
Ctrl+O / Ctrl+Shift+O 打开世界 / 打开文件（.mcstructure、.nbt、.nbts）
Ctrl+C / Ctrl+V 复制 / 粘贴选中区域（支持跨存档）
Ctrl+E / Ctrl+I 导出 / 导入选区
Ctrl+D 删除选中的区块
Ctrl+H 打开 3D 体素视图
Alt+1–Alt+4 切换维度（主世界 / 下界 / 末地 / 自定义）
Ctrl+G 跳转到坐标

构建

powershell

git clone --recursive https://github.com/bedrock-dev/BedrockMap.git

支持的 MCBE 版本

支持 Minecraft 基岩版 1.2（可能更早）及以后的世界，直到 1.21 系列（不同版本的区块格式可能不同）。

属性 说明

  • 截图导出

# 3. 编译 BedrockMap 主程序

.\scripts\build.ps1

# 4. 编译并运行（含翻译更新）
.\scripts\build_run.ps1

4.3 多存档支持

  • LevelTabWidget 管理多个存档标签页，每个标签页包含独立的 LevelPageWidget

5. 核心模块详解

5.1 bedrock-level 库

该库是一个独立的静态库，封装了 Minecraft Bedrock 版存档的底层数据操作，不依赖 Qt。

5.1.1 bl::bedrock_level — 存档管理器
代码 
路径: bedrock-level/src/bedrock_level.cpp / include/bedrock_level.h

核心职责：

  • 打开/关闭存档文件夹（读取 level.dat + 打开 LevelDB 数据库）
  • 提供 get_chunk(chunk_pos) 加载区块，支持内部缓存
  • 提供 load_raw(key) 读取原始 LevelDB 数据
  • 提供 foreach_global_keys() 遍历全局键
  • 提供 remove_chunks(positions) 批量删除区块
  • 管理全局数据：玩家数据、村庄数据、地图物品、其他 NBT

主要方法：

方法 说明
open(const std::string& root) 打开存档
close() 关闭存档
get_chunk(const chunk_pos&, chunk_load_policy) 加载区块（位掩码：Terrain/PendingTick/Actor/BlockActor/Others，默认 All）
load_raw(const std::string& key, string& value) 读取原始数据
load_actor(const std::string& raw_uid) 加载实体
load_global_data() 加载全局数据
foreach_global_keys(f) 遍历全局键
remove_chunks(std::set<chunk_pos>&) 删除区块

5.2.5 CpuMapWidget / GpuMapWidget — 地图渲染器
代码 
路径: src/cpumapwidget.cpp / include/ui/cpumapwidget.h   （CPU 渲染器）
      src/gpumapwidget.cpp / include/ui/gpumapwidget.h   （GPU 渲染器）

两个渲染器是同级、可互换的：CpuMapWidget 用 QPainter 画烘焙好的区块贴图，GpuMapWidget 把同样的烘焙数据上传进一张图集然后用 GLSL 逐像素着色（斜面光照 / AO / 阴影）。

GPU 渲染器的完整流程（每帧顺序、图集与槽位、分辨率选择、瓦片降采样与上传、着色、概览模式、诊断与 bench）见 docs/gpuMapRenderer.md。

它们都只负责自己那份绘制，通过构造函数接收同一组共享对象：

cpp 
(parent, AsyncLevelLoader*, MapView*, MapOverlays*, ImportOverlay*, MapHost*)

共享状态、编辑操作和 overlay 由 MapHost 持有（见 5.2.5.1），LevelPageWidget 只构造其中的一个渲染器，所以不存在“哪个 widget 定义相机”的歧义。

为什么不用公共基类：GpuMapWidget 必须继承 QOpenGLWidget（它本身是 QWidget）， 再加一层 widget 基类就是菱形继承；而且继承会给每个对象一份状态副本，与“两个渲染器共享同一份视图”正好相反。

上下文菜单、拖拽选区和缩放都由共享对象处理，两个渲染器的事件处理因此完全对称。

缩放级别： 快捷键 Ctrl+滚轮 缩放，范围 cfg::MINIMUM_SCALE_LEVEL ~ cfg::MAXIMUM_SCALE_LEVEL

用户交互： 由共享的 MapInteraction 实现，两个渲染器转发同一套事件：

操作 功能
鼠标拖动 平移地图
滚轮 缩放地图
中键拖动 创建选区
右键 上下文菜单（复制信息、跳转等）
双击区块 打开区块编辑器

渲染选项 (RenderOption)：

cpp 
struct RenderOption {
    enum LayerType { Biome, Terrain, Height };   // 图层类型
    enum DimType  { OverWorld, Nether, TheEnd }; // 维度类型
    enum OtherType { Grid, Coords, SlimeChunk, Actors, Village, HSA }; // 覆盖层
    DimType dim;
    LayerType layer;
    std::array<bool, 6> others;  // 各覆盖层开关
};

坐标变换（都在共享的 MapView 上，两个渲染器读同一份）：

方法 说明
blockPosToViewPos(bp) 方块坐标 → 视图坐标
chunkPosToViewPos(cp) 区块坐标 → 视图坐标
viewPosToChunkPos(vp) 视图坐标 → 区块坐标
viewPosToBlockPos(vp) 视图坐标 → 方块坐标
scaleLevel() 当前缩放级别下区块的像素宽度
chunkPosAt(pos, viewport) 用指定视口解析坐标（渲染器尺寸可能不同）
transformForViewport(size) 按指定视口大小重建变换

CPU 渲染管线：

  1. paintEvent() 入口，先 view_->setViewportSize(size()) 与 syncScaleLimits()
  2. 根据 RenderOption.layer 调用 drawTerrain() / drawBiome()
  3. 调用 foreachRegionInCamera() 遍历可见区域
  4. 对每个区域从 AsyncLevelLoader 获取缓存的渲染图像
  5. 调用 drawImageInRegion() 绘制图像
  6. 调用共享的 MapOverlays 绘制覆盖层：网格、坐标、史莱姆区块、实体、村庄、HSA、选区等

GpuMapWidget 走同一条数据来源，但把每区块一个像素的颜色/高度上传进图集，由 res/shaders/map2d.frag 逐屏幕像素着色。

选区系统 (SelectionRegion)：

模式 说明
Replace 替换选区
Add 追加到选区
Subtract 从选区移除

选区用于删除区块操作。通过浮动工具栏的按钮切换模式。选区状态存在 MapView 上，改动统一经 MapView::beginSelectionDrag() / finishSelectionDrag() 等方法，因此所有渲染器都会同步重绘。

struct ChunkRegion {

6. 数据模型

6.1 LevelDB 键结构

Minecraft Bedrock 版使用复合键存储数据，格式为：

代码 
chunk_key = prefix(1byte) + dim(4bytes) + cx(4bytes) + cz(4bytes) + tag(1byte) [+ y_index(1byte)]
字段 大小 说明
prefix 1 byte 固定为 0x00
dim 4 bytes 维度 ID
cx, cz 4+4 bytes 区块坐标
tag 1 byte 数据类型 ID
y_index 1 byte 仅 SubChunkTerrain 需要

6.2 区块数据结构

代码 
Chunk (16×?×16)
├── SubChunk (-4\~19 or 0\~15)
│   ├── Version (uint8)
│   ├── Y Index (int8)
│   ├── Layers Count (uint8)
│   └── Layer
│       ├── Bits Per Block (uint8)
│       ├── Palette Type (uint8)
│       ├── Block Indices (4096 × uint16)
│       └── Palette (NBT Compound 列表)
├── Biome3D / HeightMap
├── Entities (actor 列表)
├── Block Entities (NBT Compound 列表)
├── Pending Ticks (NBT Compound 列表)
└── Hardcoded Spawn Areas

6.3 坐标系

代码 
世界坐标 (block_pos)
    ↓ ÷16
区块坐标 (chunk_pos)  ← 包含维度 (dim=0,1,2)
    ↓
子区块 (sub_chunk)   ← Y÷16 索引，16^3 区域
    ↓
局部坐标 (rx, ry, rz)  ← 子区块内的 0~15 偏移

2.5D 体素大地图渲染方案文档

来源：newMapRender.md

一、方案概述

1.1 场景定义

  • 视角：平面固定俯视，相机不旋转、不缩放
  • 画面：只能看到体素方块的顶面，看不到侧面
  • 地图规模：最大 4K 平面（3840 × 2160），一个像素一个体素
  • 渲染方式：不构建 Mesh，不使用硬件光追

1.2 核心思路

本方案将整个体素世界抽象为两张核心数据图：

  • 地表图：每个格子的方块类型
  • 高度图：每个格子的高度值

渲染时，用一张全屏 Quad 配合 Fragment Shader，根据屏幕坐标反算地图坐标，采样地表图和高度图，合成最终画面。阴影和 AO 通过离线烘焙写入纹理，运行时零开销。

整个场景只有一个 Draw Call。

1.3 为什么不用 Mesh

  • 只能看到顶面 → 没有立体几何需求
  • 固定视角 → 不需要动态几何
  • 不建 Mesh → 数据更新时无需重建顶点缓冲
  • 数据即纹理 → 动态加载和更新极其轻量

二、数据设计

2.1 核心数据图

数据 内容 建议格式 说明
地表图 方块类型 ID uint8 / uint16 决定颜色/材质
高度图 每格高度值 uint8 / uint16 决定遮挡、位移
AO 图 烘焙环境光遮蔽 uint8 离线生成
阴影图 烘焙阴影 uint8 离线生成
光照图（可选） 烘焙光照 uint8 / vec3 离线生成

2.2 分辨率与显存估算

以 3840 × 2160 为例：

纹理 格式 大小
地表图 uint16 ~16 MB
高度图 uint16 ~16 MB
AO 图 uint8 ~8 MB
阴影图 uint8 ~8 MB
合计 ~48 MB

结论：4K 全图完全可以一次性加载进显存，无需动态加载。

2.3 数据组织（可选动态加载）

如果未来地图更大或显存受限，可按 Chunk 分块：

代码 
世界地图 (4K)
  └── Region (512×512)
        └── Chunk (64×64)
              └── Tile (单格)

每个 Chunk 对应纹理图集中的一块区域，可独立加载、卸载、更新。

三、渲染管线

3.1 整体流程

代码 
┌─────────────────────────────────────────┐
│  1. 全屏 Quad（4 顶点）                  │
│  2. Fragment Shader：                    │
│     - 屏幕坐标 → 地图坐标                │
│     - 采样地表图、高度图、AO、阴影       │
│     - 高度位移 + 光照合成                │
│  3. 输出最终颜色                         │
└─────────────────────────────────────────┘

3.2 全屏 Quad

  • 4 个顶点，覆盖整个视口
  • 顶点属性只需位置（vec2）和 UV（vec2）
  • 一次 vkCmdDraw，一个 Draw Call

3.3 Fragment Shader 逻辑

glsl 
// 伪代码
vec2 mapCoord = screenToMap(fragUV);       // 屏幕 → 地图坐标
uint terrain  = sampleTerrain(mapCoord);   // 采样地表图
float height  = sampleHeight(mapCoord);    // 采样高度图
float ao      = sampleAO(mapCoord);        // 采样 AO
float shadow  = sampleShadow(mapCoord);    // 采样阴影

vec3 baseColor = lookupColor(terrain);     // 方块类型 → 颜色
vec2 offset    = heightToOffset(height);   // 高度 → 屏幕位移（2.5D 立体感）
vec3 finalColor = baseColor * ao * shadow;

3.4 高度位移（2.5D 立体感）

高度图除了算 AO 和阴影，还能产生视觉位移：

  • 高处格子沿固定方向（如斜上方）偏移若干像素
  • 产生轻微的立体感，无需真正的 3D 几何
  • 偏移方向由固定光照方向决定

3.5 坐标映射

固定俯视下，屏幕坐标到地图坐标是一个简单的线性变换：

代码 
mapX = (screenX - cameraOffsetX) * scale
mapY = (screenY - cameraOffsetY) * scale

无需透视投影，无需矩阵变换。

四、AO 烘焙

4.1 原理

2.5D 高度场下，AO 取决于邻域高度差：

  • 周围格子比自己高 → 产生遮蔽
  • 高度差越大 → AO 越强

4.2 计算方法

对每个格子，检查周围 8 个邻居：

cpp 
float ao = 0.0;
for (each neighbor in 8 directions) {
    float diff = neighborHeight - currentHeight;
    if (diff > 0) {
        ao += clamp(diff / maxDiff, 0.0, 1.0) * weight;
    }
}
ao = 1.0 - ao * aoStrength;

4.3 输出

  • 将 AO 值写入 uint8 纹理
  • 运行时直接采样，零计算
  • 因视角和光照固定，AO 只需烘焙一次

五、阴影烘焙

5.1 原理

固定方向光下，每个格子的阴影取决于沿光方向是否被更高的格子挡住。

5.2 四叉树加速

代码 
1. 将高度图构建为四叉树
2. 对每个格子，沿光方向投射一条射线
3. 用四叉树快速跳过不需要检测的区域
4. 判断是否被遮挡

四叉树的作用：

  • 快速跳过远处不可能遮挡的区域
  • 快速定位可能遮挡的局部范围
  • 把 O(n) 的逐格检测降到接近 O(log n)

5.3 阴影方向

固定光照方向下，阴影方向固定：

  • 例如光从左上角来 → 阴影向右下延伸
  • 每个格子的阴影只取决于其右上方的格子

5.4 输出

  • 将阴影值写入 uint8 纹理（0 = 全阴影，255 = 无阴影）
  • 运行时直接采样
  • 只需烘焙一次（静态地图）

5.5 软阴影（可选）

  • 对阴影边缘做多次采样取平均
  • 或多级四叉树采样，产生半影效果
  • 烘焙时完成，运行时零开销

六、动态加载（可选）

6.1 何时需要

  • 地图超过 4K，或显存受限
  • 地形会动态变化

6.2 核心优势

因为没有 Mesh：

  • 数据更新只需更新纹理局部区域
  • 不需要重建顶点缓冲
  • 不需要重新提交绘制命令

6.3 纹理图集方案

代码 
+----+----+----+----+
| C0 | C1 | C2 | C3 |
+----+----+----+----+
| C4 | C5 | C6 | C7 |
+----+----+----+----+
| ...                |
+----+----+----+----+
  • 每个 Chunk 占图集中的一块
  • 加载 = 往图集写数据
  • 卸载 = 标记区域可复用

6.4 更新流程

代码 
1. 检测需要加载/卸载的 Chunk
2. 生成或读取 Chunk 数据
3. 计算 AO、阴影（仅受影响的 Chunk）
4. 用 staging buffer 上传到纹理图集
5. 标记 Chunk 状态

6.5 上传优化

  • 用 staging buffer + 异步传输队列
  • 分帧上传，避免卡顿
  • 预加载相邻一圈 Chunk，避免边缘闪烁
  • 单个 64×64 Chunk 的 uint8 数据仅 4KB，开销极小

八、性能预期

指标 预期值
Draw Call 1
顶点数 4
三角形数 2
纹理采样 每像素 4~5 次
显存占用 ~50 MB（4K 全图）
运行时 CPU 开销 极低（仅更新 Uniform）
帧率 4K 60fps 轻松达成

性能瓶颈几乎全在 Fragment Shader 的采样和合成上，现代 GPU 完全无压力。

九、方案对比

方案 是否适合
建 Mesh + 光栅化 ❌ 多余
硬件光追 ❌ 完全不需要
软件高度场求交（四叉树） ✅ 用于烘焙阴影/AO
全屏 Quad + 高度图 ✅ 最终渲染方式
离线烘焙 AO + 阴影 ✅ 运行时零开销

十、实施步骤

  1. 准备数据：地表图 + 高度图
  2. 烘焙 AO：按邻域高度差计算，写入纹理
  3. 烘焙阴影：四叉树 + 高度场求交，写入纹理
  4. 搭建渲染：全屏 Quad + Fragment Shader
  5. 实现坐标映射：屏幕 → 地图坐标
  6. 合成画面：采样 + 高度位移 + 光照
  7. （可选）动态加载：纹理图集 + 局部更新
  8. 调优：采样精度、位移强度、AO/阴影强度

十一、关键注意事项

  1. 采样器用最近邻：保持体素像素感，避免模糊
  2. 纹理格式对齐：uint8/uint16 注意 Vulkan 格式支持
  3. Y 轴方向：Vulkan 裁剪空间 Y 向下，注意地图坐标方向
  4. 高度位移方向：固定光照方向决定偏移方向，保持一致性
  5. 动态更新：优先用局部纹理更新，避免整图重传
  6. 预加载：相机移动时提前加载相邻 Chunk
